# OctoDash bridge

Мост между сессиями Claude Code и настольным TFT-экраном. Единственный
долгоживущий процесс: держит правду о состоянии всех сессий, принимает события от
хуков по HTTP и шлёт агрегированный снэпшот на ESP по USB serial.

```
сессии claude ──(хуки)──▶ bridge.py ──(USB serial)──▶ ESP + TFT
```

Прошивка ESP лежит в `../firmware/octodash/`.

## Установка

```bash
# из директории bridge/
python -m venv ../.venv            # если ещё нет
../.venv/Scripts/python.exe -m pip install -r requirements.txt   # Windows
# ../.venv/bin/python -m pip install -r requirements.txt          # Linux/macOS
```

Зависимости: `pyserial` (обязателен), `psutil` (опционально — иначе используется
`ctypes`/`os.kill` фолбэк для проверки живости PID).

## Запуск

```bash
python bridge.py                   # боевой режим
OCTO_MOCK=1 python bridge.py       # mock: 6 фейковых сессий, без реальных хуков
OCTO_DEBUG=1 python bridge.py      # подробный лог (каждый пуш в serial)
```

Второй запущенный экземпляр молча завершится (singleton через бинд порта).

### Имена карточек

`name = basename(cwd)` — последний сегмент рабочей директории (для worktree это
имя папки/ветки). Перед отправкой на ESP имя проходит две обработки в мосту
(`display_name`), т.к. экран «тупой» и с ограничениями:

- **Транслитерация RU → латиница** (`каталог → katalog`). Классический шрифт
  Adafruit GFX — CP437, кириллицу не умеет (рисует мусор), поэтому переводим в ASCII.
- **Обрезка по центру** до `OCTO_NAME_MAX` символов с маркером `~`
  (`feature-knowledgebase-migration-v2 → feature-~tion-v2`). Серединная, а не с
  головы — чтобы worktree с общим префиксом оставались различимыми по хвосту.

Практический предел читаемости на карточке ~16–17 символов (ширина ячейки 102px,
шрифт 6px/символ). Если нужен настоящий кириллический текст — это правка прошивки
(UTF-8-декод + шрифт с кириллическими глифами, напр. U8g2).

### Serial-порт: автоопределение

По умолчанию `OCTO_SERIAL_PORT=auto` — мост сам ищет ESP по USB VID:PID известных
UART-чипов (CH340 у WeMos D1 mini, CH9102, CP210x, FTDI). Если совпадений нет, но
доступен ровно один порт — берётся он. Если портов несколько и ни один не опознан —
задайте порт явно через `OCTO_SERIAL_PORT`. Поиск повторяется при каждом
переоткрытии, поэтому переподключение USB подхватывается автоматически.

| `OCTO_BRIDGE_PORT` | `8787` | порт (он же арбитр singleton) |
| `OCTO_SERIAL_PORT` | `auto` | `auto` — автоопределение по USB VID:PID; иначе явный порт (`COM3`, `/dev/ttyUSB0`) |
| `OCTO_SERIAL_BAUD` | `115200` | скорость serial |
| `OCTO_HEARTBEAT_SEC` | `5` | период heartbeat-пуша |
| `OCTO_REAPER_SEC` | `2` | период проверки живости PID |
| `OCTO_DEBOUNCE_MS` | `100` | дебаунс пушей при серии событий |
| `OCTO_MAX_SESSIONS` | `6` | максимум карточек (сетка 3×2) |
| `OCTO_NAME_MAX` | `16` | лимит длины имени карточки (транслит + обрезка по центру) |
| `OCTO_STALE_IDLE_HOURS` | `4` | IDLE-сессия без активности столько часов уходит с экрана (`0` — не скрывать) |
| `OCTO_STALE_ANY_HOURS` | `24` | то же для любого состояния, включая WORKING/WAITING (`0` — не скрывать) |

| `OCTO_REGISTRY_ROOT` | — | каталог реестра; пусто → `~/.claude` |
| `OCTO_RECONCILE_GRACE_SEC` | `30` | молодая сессия столько защищена от удаления сверкой |
| `OCTO_MOCK` | `0` | `1` — режим фейковых сессий |
| `OCTO_HOOK_TIMEOUT` | `0.5` | таймаут запроса в `octo-notify.py` |
| `OCTO_LOG_FILE` | — | пусто → `~/.local/state/octodash/bridge.log` (`%LOCALAPPDATA%` на Windows); `-` — не писать в файл |

## Что попадает на экран

Слотов шесть, а сессий бывает больше — поэтому мост **отбирает**, а не просто режет
список по порядку:

- приоритет у состояния: `WORKING` → `ERROR` → `WAITING` → `IDLE`, внутри группы —
  по свежести последней активности;
- **брошенные скрываются**: `IDLE` без активности дольше `OCTO_STALE_IDLE_HOURS`,
  любое состояние — дольше `OCTO_STALE_ANY_HOURS` (статус тоже протухает: «работает»
  сутки без единого события значит, что сессию бросили). Скрытие ≠ удаление — сессия
  остаётся в мосту и вернётся на экран с первым признаком жизни;
- свободный слот остаётся пустым: «здесь никто не работает» — это правда, а карточка
  трёхдневной давности только мешает читать экран;
- **место** карточки определяется временем старта сессии, а не приоритетом, — иначе
  карточки прыгали бы при каждой смене статуса.

Почему скрытая карточка не видна, показывает `octoctl debug` (колонка «причина»).

## Сверка с реестром сессий Claude Code

Claude Code сам ведёт на диске список активных сессий (`~/.claude/sessions/<pid>.json`,
`~/.claude/daemon/roster.json`, `~/.claude/jobs/*/state.json`). Мост раз в
`OCTO_REGISTRY_SEC` сверяет с ним состав. Это закрывает то, чего liveness по PID не
видит принципиально:

- сессию **без PID** (фоновая, или хук не смог его резолвить) — по PID она бессмертна;
- смену `session_id` **внутри живого процесса** (`/clear`, resume, fork): старый id
  мёртв, а PID процесса жив, и карточка-призрак остаётся навсегда;
- **восстановление после рестарта моста**: состав поднимается сразу, не дожидаясь
  первого хука в каждой сессии.

Формат реестра недокументирован, поэтому разбор — best-effort: непонятная запись
пропускается, а если реестр не прочитался вовсе, сверка **ничего не удаляет** и мост
работает по-старому (хуки + liveness по PID). Запись реестра проверяется на живость
по PID **и** `procStart` (защита от переиспользования PID), а `jobs/*/state.json`
служит только источником статуса — там лежат и завершённые задания.

## Веб-морда

Открыть <http://localhost:8787/> в браузере — страница со сводкой (сколько сессий, что
на экране, состояние serial и реестра), таблицей всех сессий (статус, PID, тишина,
причина скрытия) и кнопками «Сверить с реестром» / «Сбросить состав» / «скрыть карточку».
Данные тянутся из `/debug` раз в 2 секунды.

Страница самодостаточна: HTML+CSS+JS инлайном, ни одного внешнего ресурса — мост не
ходит в сеть и не зависит от неё, чтобы показать своё состояние.

`GET /` различает клиента по `Accept`: браузер получает морду, `curl localhost:8787` —
снэпшот JSON, как раньше. Явный адрес страницы — `/ui`.

Мост слушает `127.0.0.1`, поэтому морда доступна только локально. Биндить `0.0.0.0`
не стоит: кнопка «Сбросить состав» не имеет авторизации.

## octoctl — управление живым мостом

```bash
python octoctl.py status     # что сейчас на экране
python octoctl.py debug      # всё состояние: сессии, PID, почему скрыты (--json — машинно)
python octoctl.py resync     # форс-сверка с реестром
python octoctl.py reset      # забыть все сессии и пересобрать состав из реестра
python octoctl.py hide 7e12  # убрать карточку с экрана (хватает префикса id)
python octoctl.py restart    # перезапустить процесс моста
```

Те же операции по HTTP: `GET /status`, `GET /debug`, `GET /ui`, `POST /resync`,
`POST /reset`, `DELETE /sessions/<id>`.

`hide` **скрывает, а не удаляет**: удалённую сессию сверка вернула бы обратно в пределах
`OCTO_REGISTRY_SEC` (она же есть в реестре), и кнопка выглядела бы сломанной. Заглушка
снимается сама, как только сессия проявит активность. Мусор, которого в реестре нет,
всё равно исчезнет — его добьёт сверка.

## Установка хуков Claude Code

1. Скопировать обёртку в каталог хуков:
   - Linux/macOS: `cp octo-notify.py ~/.claude/hooks/`
   - Windows: `copy octo-notify.py %USERPROFILE%\.claude\hooks\`
2. Добавить блок `hooks` в `~/.claude/settings.json` (user-level — работает во всех
   проектах и worktree). Готовые примеры для Linux и Windows — в
   `hooks-settings.example.json`. Путь к скрипту в `command` заменить на реальный.

Маппинг событий: `SessionStart→start` (+pid), `UserPromptSubmit→working`,
`PostToolUse→working`, `Notification→waiting`, `Stop→idle`, `SessionEnd→end`,
`StopFailure→error`. `PostToolUse→working` возвращает карточку в зелёный после одобрения
тула (иначе «застряла бы» на жёлтом). `PreToolUse` не вешаем — дублировал бы без пользы.

## Команда запуска

Обёртки идемпотентно поднимают мост, затем запускают `claude`:

- Linux/macOS: `./octo-run.sh [аргументы claude...]`
- Windows: `.\octo-run.ps1 [аргументы claude...]`

Удобно завести алиас `claude` → соответствующий скрипт.

## Тесты

Автотесты (pytest). Ядро моста спроектировано под тестируемость: время, проверка
PID и «сток» снэпшотов внедряются в `Bridge(...)`, поэтому автомат, порядок карточек,
reaper, формат JSON и автоопределение порта проверяются синхронно — без железа и sleep.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest                 # из директории bridge/ — 172 теста + покрытие ≥90%
python -m pytest tests/test_bridge.py::test_reap_removes_dead_pids   # один тест
python -m pytest -k autodetect   # по имени
```

Ручные проверки на живой системе:

```bash
# singleton — второй инстанс молча выходит
python bridge.py &            # первый
python bridge.py; echo $?     # → 0, сразу выходит

# приём события руками
curl -s -XPOST localhost:8787/event \
  -d '{"session_id":"t1","event":"start","cwd":"/home/e/proj","pid":'$$'}'
curl -s localhost:8787/status   # посмотреть текущий снэпшот
curl -s localhost:8787/debug    # всё состояние: сессии, PID, причины скрытия
```

Смотреть, что уходит на ESP, без железа: запустить с `OCTO_DEBUG=1` — каждый
снэпшот логируется строкой `→ ESP: {...}`.
