# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

OctoDash — настольный гаджет-компаньон. Маленький TFT-экран (ILI9341, 320×240) показывает пиксельный
«аквариум» из осьминогов — по одному на каждую активную сессию Claude Code, анимированного по статусу
сессии. Этот репозиторий содержит **Python-мост** (основная задача) и обвязку хуков Claude Code.
Прошивка ESP8266 и железо уже существуют и считаются фиксированным контрактом — менять их не нужно.

Поток данных:
`сессии claude ──(хуки)──▶ bridge.py (единственный долгоживущий процесс) ──(USB serial)──▶ ESP + TFT`

- Сессии эфемерны: заявляют о себе только через хуки, ничего не хранят.
- **Мост** — единственный источник правды: держит состояние всех сессий и шлёт агрегированный
  снэпшот на экран.
- ESP — «тупой» рендерер: получает полные снэпшоты и анимирует.

## Структура репозитория

```

  octo-notify.py            тонкая обёртка-хук (устанавливается в ~/.claude/hooks/)
  octo-run.sh / .ps1        команды запуска (Linux / Windows): поднять мост + запустить claude
  hooks-settings.example.json   готовые блоки hooks для ~/.claude/settings.json
  conftest.py, pytest.ini   конфиг тестов (bridge.py в sys.path, покрытие ≥90%)
  tests/test_bridge.py      pytest-набор (66 тестов, ~97% покрытия ядра)
  requirements.txt          pyserial (обязателен), psutil (опционально)
  requirements-dev.txt      + pytest, pytest-cov
  README.md                 установка, env-переменные, тесты
```

Мост запускается интерпретатором `.venv\Scripts\python.exe` (3.12). `pyserial`,
`psutil`, `pytest`, `pytest-cov` уже установлены в `.venv`.

## Архитектура кода: тестируемость через инъекцию зависимостей

`bridge.py` разделён на **чистое ядро** и **IO/поточную обвязку**:
- Ядро `Bridge` не знает ни о потоках, ни о serial, ни о реальном времени. В
  конструктор внедряются: `clock` (часы), `is_alive` (проверка PID), `sink`
  (получатель снэпшота). Методы `handle_event`, `build_snapshot`, `snapshot_line`,
  `reap`, `push` синхронны и детерминированы — тестируются без железа и без `sleep`.
- `Sink` — протокол получателя строки-снэпшота. В проде `SerialSink` (serial с
  автопереоткрытием), в тестах `CollectingSink`. `LoggingSink` — фолбэк, когда serial нет.
- Обвязка (`sender_loop`/`reaper_loop`/`mock_loop`, HTTP-сервер, `main`) — тонкая; в
  покрытии помечена `# pragma: no cover` там, где проверяется только интеграционно.

При доработке ядра **не тащи в него потоки/IO** — держи детерминированным и добавляй
тест в `tests/test_bridge.py`. HTTP-слой покрыт интеграционным тестом на эфемерном порту.

Команды тестов (из `bridge/`):
```bash
python -m pytest                 # весь набор + покрытие (гейт ≥90% в pytest.ini)
python -m pytest -k autodetect   # по подстроке имени
python -m pytest tests/test_bridge.py::test_reap_removes_dead_pids   # один тест
```

## Автоопределение serial-порта

`OCTO_SERIAL_PORT=auto` (дефолт) → `autodetect_port()` ищет ESP по USB VID:PID
известных UART-чипов (`KNOWN_USB_IDS`: CH340, CH9102, CP210x, FTDI); фолбэк —
единственный доступный порт. Резолв повторяется при каждом переоткрытии, поэтому
переподключение USB подхватывается. Явный порт в env отключает автоопределение.
`autodetect_port` принимает `list_ports_fn` — ради тестов без железа.

## Окружение: спека под Linux, машина разработки — Windows

Спецификация написана под Linux Mint. Эта машина — Windows 11. Мост должен быть кроссплатформенным:
- **Serial-порт**: по умолчанию `auto` (автоопределение, см. ниже); ручное значение —
  `COMx` на Windows или `/dev/ttyUSB0` на Linux через `OCTO_SERIAL_PORT`. Не хардкодить путь.
- **Живость по PID**: `os.kill(pid, 0)` работает на обеих ОС, но кидает разные исключения — лучше
  `psutil.pid_exists`, иначе оборачивать `os.kill` и на `ProcessLookupError`, и на `PermissionError`.
- **Отвязка при запуске**: в спеке `setsid`; на Windows его нет — использовать `DETACHED_PROCESS` /
  `CREATE_NEW_PROCESS_GROUP`. Команда запуска платформозависима.
- Интерпретатор: `.venv\Scripts\python.exe` (3.12). Зависимости: `pyserial` (обязателен),
  `psutil` (опционально).

## Неочевидные инварианты (не «чинить» их)

- **Singleton через бинд порта, не lock-файл.** На старте мост биндит `127.0.0.1:8787`. Бинд удался →
  мы единственный инстанс. Бинд упал с `EADDRINUSE` → мост уже запущен, **молча выходим с кодом 0**
  (это не ошибка). Тот же сокет — HTTP-точка приёма хуков. Краш → порт освобождается сам, протухших
  локов не бывает. Благодаря этому команда запуска идемпотентна.
- **Живость только по PID, никогда по таймауту.** Сессия в `WAITING` может законно молчать сколько
  угодно (ждёт человека) — таймаут прибил бы её ошибочно. Поток-reaper проверяет живость по PID.
- **Снэпшоты полные, не дельты.** Одна строка JSON на снэпшот, с завершающим `\n`. Проще и надёжнее
  для ESP с малой памятью. Короткие имена полей ради RAM на ESP: `id`, `name`, `state`.
  Формат провода: `{"v":1,"sessions":[{"id":"abc","name":"proj","state":0}, ...]}`
- **Коды состояний фиксированы enum'ом прошивки:** `WORKING=0, WAITING=1, IDLE=2, ERROR=3`.
- **Имя карточки готовит мост, не прошивка.** `display_name(cwd)` = `basename` →
  транслит RU→латиница (шрифт ESP — CP437, кириллицу не умеет) → обрезка по центру
  (`~`) до `OCTO_NAME_MAX`. Серединная обрезка намеренная: worktree с общим префиксом
  иначе схлопнулись бы в одинаковые огрызки. Прошивка остаётся «тупой» — рисует ASCII.
- **`MAX_SESSIONS=6`** (сетка 3×2). Если сессий больше — слать первые 6 по `first_seen`, остальное
  логировать (карусель — будущая доработка). Порядок карточек стабильный — сортировка по `first_seen`,
  чтобы карточки не «прыгали» при обновлениях.
- **Хуки не должны блокировать Claude.** Обработчик `POST /event` всегда быстро возвращает `200`;
  ошибки — в лог, никаких задержек. Обёртка `octo-notify.py` использует короткий таймаут запроса
  (~0.5с), глотает все ошибки и **всегда выходит с кодом 0**.

## Внутренности моста (целевой дизайн)

- **Конкурентность**: основной поток = HTTP-сервер (приём хуков); поток-reaper (проверка PID раз в
  `OCTO_REAPER_SEC`, дефолт 2с, пушит при изменении); таймер heartbeat (пуш раз в `OCTO_HEARTBEAT_SEC`,
  дефолт 5с — чтобы перезагруженный/переподключённый ESP восстановил картинку). Доступ к словарю
  `sessions` — под одним `threading.Lock`; запись в serial сериализовать под локом (или через
  очередь), чтобы строки не перемешивались.
- **Модель сессии** по ключу `session_id`: `{session_id, name, state, pid, first_seen, last_event}`.
  `name = os.path.basename(cwd.rstrip('/'))` (даёт имена git-worktree / папок).
- **Конечный автомат** (событие → действие): `start`→создать сессию, `state=IDLE`, запомнить `pid`;
  `working`→WORKING; `waiting`→WAITING; `idle`→IDLE; `error`→ERROR; `end`→удалить сессию.
  Неизвестное событие → лог и игнор. Не-`start` событие для неизвестного `session_id` → создать
  сессию на лету с этим состоянием и `pid=None` (хук мог прилететь после рестарта моста).
- **Триггеры пуша**: любое видимое изменение состояния (с дебаунсом `OCTO_DEBOUNCE_MS`, дефолт 100мс,
  чтобы серия событий схлопнулась в один пуш) ИЛИ периодический heartbeat.
- **Устойчивость serial**: если порт недоступен (ESP не воткнут) — мост не падает: логирует,
  продолжает принимать хуки, периодически пытается переоткрыть порт; heartbeat перерисует после
  переподключения.

## Обвязка хуков

`octo-notify.py` читает JSON-конверт хука со stdin (`session_id`, `transcript_path`, `cwd`,
`hook_event_name`), мапит событие и шлёт `POST` на мост. Для `SessionStart` добавляет
`pid = os.getppid()` (родитель обёртки = процесс `claude` — единственный захват PID за сессию,
нужен для liveness).

Маппинг хук Claude Code → `event` моста:
`SessionStart`→`start` (+pid), `UserPromptSubmit`→`working`, `PostToolUse`→`working`,
`Notification`→`waiting`, `Stop`→`idle`, `SessionEnd`→`end`, `StopFailure`→`error` (опц.),
`PreToolUse` (matcher `Task`)→`subagent`, `SubagentStop`→`subagent_done`.
`PostToolUse`→`working` снимает «застревание» на `WAITING` после одобрения тула.
Регистрировать на **user-уровне** (`~/.claude/settings.json`), чтобы работало во всех
проектах и worktree.

**Суб-агенты.** `PreToolUse` вешается с **matcher `Task`** (фильтр по имени инструмента →
хук срабатывает только на спавн суб-агента, без спама). Мост держит `Session.subagents`:
`subagent` +1, `subagent_done` −1, сброс в 0 на `idle`/`start` (страховка). В снэпшот идёт
`"sub":N` (кап 5), прошивка рисует N пузырьков-искр на орбите вокруг осьминога.

PID для liveness определяет `resolve_claude_pid()` в обёртке: обход дерева процессов вверх и
матч по **имени** процесса/basename (`claude`/`claude.exe`/`claude-code`), не по подстроке во
всей cmdline (иначе ложно ловятся предки с `~/.claude/...` в аргументах). Не нашли уверенно →
`pid=None` (мост не реапит по liveness — безопаснее, чем убить карточку по PID транзиентного шелла).

## Конфигурация (env-переменные с дефолтами)

```
OCTO_BRIDGE_HOST   = 127.0.0.1
OCTO_BRIDGE_PORT   = 8787
OCTO_SERIAL_PORT   = auto           # auto = автоопределение по USB VID:PID; или COMx / /dev/ttyUSB0
OCTO_SERIAL_BAUD   = 115200
OCTO_HEARTBEAT_SEC = 5
OCTO_REAPER_SEC    = 2
OCTO_DEBOUNCE_MS   = 100
OCTO_MAX_SESSIONS  = 6
OCTO_NAME_MAX      = 16  # лимит имени карточки: транслит RU→латиница + обрезка по центру ('~')
OCTO_MOCK          = 0   # 1 = генерить 6 фейковых сессий с меняющимися состояниями, без реальных хуков
OCTO_DIAG          = 0   # 1 = диаг-логи: PUSH #N (reason/dt/n/serial/статусы), переоткрытия serial,
                         #     чтение обратного канала ESP («← ESP: {boot/stat/badjson}»). Включает DEBUG.
OCTO_SERIAL_NO_RESET = 0 # 1 = открывать serial без дёргания DTR/RTS — чтобы (пере)открытие порта
                         #     не ресетило ESP (кандидат-фикс редких «чёрных морганий»)
OCTO_LOG_FILE      =     # путь к файлу — дублировать логи туда (чтобы «сыпались локально»)
```

## Прошивка (firmware/octodash/octodash.ino)

Скетч построен на рабочей базе с проверенной анимацией; менять стиль отрисовки и
палитру без нужды не стоит. Специфика:
- Дисплей: `tft.setRotation(3)`; пины `TFT_CS=D8, TFT_DC=D4, TFT_RST=D3`.
- Плавность — через off-screen `GFXcanvas16 octoBuf(60,72)` на одного осьминога:
  кадр собирается в RAM, затем один `drawRGBBitmap` (без чёрной вспышки).
- `enum State { WORKING, WAITING, IDLE, ERR }` = 0,1,2,3 — совпадает с кодами моста.
- **Diff** в `applySnapshot()`: полная перерисовка (`redrawAll` = `drawGrid` + рамки)
  только если сменился состав / имя / статус — иначе `loop()` просто анимирует дальше.
  Heartbeat моста шлёт тот же снэпшот раз в 5с — diff видит «без изменений», лишней
  перерисовки нет.
- Пустые слоты (сессий < 6) — просто фон, без осьминога.
- Библиотеки: Adafruit GFX, Adafruit ILI9341, ArduinoJson (v6).

## Запуск и тестирование моста

```bash
# из bridge/
.venv/Scripts/python.exe bridge/bridge.py                # боевой режим
OCTO_MOCK=1 .venv/Scripts/python.exe bridge/bridge.py    # 6 фейковых сессий, без хуков
OCTO_DEBUG=1 .venv/Scripts/python.exe bridge/bridge.py   # видно строки «→ ESP: {...}»
```

Без железа посмотреть, что уходит на ESP: запустить с `OCTO_DEBUG=1` (каждый снэпшот
логируется) или дёрнуть `GET /status`. Чек-лист ручной проверки (Definition of Done):
- **Singleton**: запустить мост дважды — второй молча выходит с кодом 0, первый работает.
- **Liveness**: `POST /event` со `start` и живым PID, убить процесс — карточка исчезает
  в пределах `OCTO_REAPER_SEC`.
- **Дебаунс**: серия быстрых событий → на serial ровно один снэпшот (видно с `OCTO_DEBUG=1`).
- **Отключение ESP**: выдернуть USB на работающем мосту — мост не падает; воткнуть обратно —
  heartbeat перерисует.

Тест-фреймворка и шага сборки пока нет; при появлении тестов добавить `pytest`.
