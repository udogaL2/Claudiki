# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

OctoDash — настольный гаджет-компаньон. Маленький TFT-экран (ILI9341, 320×240) показывает пиксельный
«аквариум» из осьминогов — по одному на каждую активную сессию Claude Code, анимированного по статусу
сессии. Этот репозиторий содержит **Python-мост** (основная задача) и обвязку хуков Claude Code.
Прошивка ESP8266 и железо уже существуют и считаются фиксированным контрактом — менять их не нужно.

Поток данных:
`сессии claude ──(хуки)──▶ bridge.py (единственный долгоживущий процесс) ──(USB serial)──▶ ESP + TFT`

- Сессии эфемерны: заявляют о себе только через хуки, ничего не хранят.
- **Мост** — единственный источник правды: держит состояние всех сессий и шлёт агрегированный
  снэпшот на экран.
- ESP — «тупой» рендерер: получает полные снэпшоты и анимирует.

## Структура репозитория

```

  octoctl.py                CLI управления живым мостом: status/debug/resync/reset/rm/restart
  octo-run.sh / .ps1        команды запуска (Linux / Windows): поднять мост + запустить claude
  hooks-settings.example.json   готовые блоки hooks для ~/.claude/settings.json
  conftest.py, pytest.ini   конфиг тестов (bridge.py в sys.path, покрытие ≥90%)
  tests/test_bridge.py      pytest-набор ядра (~99% покрытия bridge.py)
  tests/test_hook.py        тесты обёртки-хука
  tests/test_octoctl.py     тесты CLI (сеть подменяется)
  requirements.txt          pyserial (обязателен), psutil (опционально)
  requirements-dev.txt      + pytest, pytest-cov
  README.md                 установка, env-переменные, тесты
firmware/

  WIRING.md                 распиновка, обоснование выбора пинов, обработка энкодера
  BUILD.md                  сборка железа: компоненты, пошаговая пайка, чек-лист приёмки
```

**Новые экраны и анимации сначала рисуются в эмуляторе** (`tools/octodash-preview.html`,
он же опубликован как артефакт), и только после утверждения переносятся в прошивку.
Итерация на железе медленная, а эмулятор считает те же пиксели теми же примитивами
Adafruit_GFX и вдобавок показывает цену кадра в SPI-миллисекундах.

Мост запускается интерпретатором `.venv\Scripts\python.exe` (3.12). `pyserial`,
`psutil`, `pytest`, `pytest-cov` уже установлены в `.venv`.

## Архитектура кода: тестируемость через инъекцию зависимостей

`bridge.py` разделён на **чистое ядро** и **IO/поточную обвязку**:
- Ядро `Bridge` не знает ни о потоках, ни о serial, ни о реальном времени. В
  конструктор внедряются: `clock` (часы), `is_alive` (проверка PID), `sink`
  (получатель снэпшота). Методы `handle_event`, `build_snapshot`, `snapshot_line`,
  `reap`, `push` синхронны и детерминированы — тестируются без железа и без `sleep`.
- `Sink` — протокол получателя строки-снэпшота. В проде `SerialSink` (serial с
  автопереоткрытием), в тестах `CollectingSink`. `LoggingSink` — фолбэк, когда serial нет.
- Обвязка (`sender_loop`/`reaper_loop`/`mock_loop`, HTTP-сервер, `main`) — тонкая; в
  покрытии помечена `# pragma: no cover` там, где проверяется только интеграционно.

При доработке ядра **не тащи в него потоки/IO** — держи детерминированным и добавляй
тест в `tests/test_bridge.py`. HTTP-слой покрыт интеграционным тестом на эфемерном порту.

Команды тестов (из `bridge/`):
```bash
python -m pytest                 # весь набор + покрытие (гейт ≥90% в pytest.ini)
python -m pytest -k autodetect   # по подстроке имени
python -m pytest tests/test_bridge.py::test_reap_removes_dead_pids   # один тест
```

## Автоопределение serial-порта

`OCTO_SERIAL_PORT=auto` (дефолт) → `autodetect_port()` ищет ESP по USB VID:PID
известных UART-чипов (`KNOWN_USB_IDS`: CH340, CH9102, CP210x, FTDI); фолбэк —
единственный доступный порт. Резолв повторяется при каждом переоткрытии, поэтому
переподключение USB подхватывается. Явный порт в env отключает автоопределение.
`autodetect_port` принимает `list_ports_fn` — ради тестов без железа.

## Окружение: спека под Linux, машина разработки — Windows

Спецификация написана под Linux Mint. Эта машина — Windows 11. Мост должен быть кроссплатформенным:
- **Serial-порт**: по умолчанию `auto` (автоопределение, см. ниже); ручное значение —
  `COMx` на Windows или `/dev/ttyUSB0` на Linux через `OCTO_SERIAL_PORT`. Не хардкодить путь.
- **Живость по PID**: `os.kill(pid, 0)` работает на обеих ОС, но кидает разные исключения — лучше
  `psutil.pid_exists`, иначе оборачивать `os.kill` и на `ProcessLookupError`, и на `PermissionError`.
- **Отвязка при запуске**: в спеке `setsid`; на Windows его нет — использовать `DETACHED_PROCESS` /
  `CREATE_NEW_PROCESS_GROUP`. Команда запуска платформозависима.
- Интерпретатор: `.venv\Scripts\python.exe` (3.12). Зависимости: `pyserial` (обязателен),
  `psutil` (опционально).

## Неочевидные инварианты (не «чинить» их)

- **Singleton через бинд порта, не lock-файл.** На старте мост биндит `127.0.0.1:8787`. Бинд удался →
  мы единственный инстанс. Бинд упал с `EADDRINUSE` → мост уже запущен, **молча выходим с кодом 0**
  (это не ошибка). Тот же сокет — HTTP-точка приёма хуков. Краш → порт освобождается сам, протухших
  локов не бывает. Благодаря этому команда запуска идемпотентна.
- **Удаление сессии — только по факту (PID/реестр), никогда по таймауту.** Сессия в `WAITING` может
  законно молчать сколько угодно (ждёт человека) — таймаут удалил бы её ошибочно. Поток-reaper
  проверяет живость по PID, а сверка (`reconcile`) — по реестру сессий Claude Code.
  **Скрытие с экрана — другое дело:** брошенную сессию мост не показывает (см. отбор карточек ниже),
  но из состояния не удаляет, и она вернётся с первым признаком жизни.
- **Снэпшоты полные, не дельты.** Одна строка JSON на снэпшот, с завершающим `\n`. Проще и надёжнее
  для ESP с малой памятью. Короткие имена полей ради RAM на ESP: `id`, `name`, `state`.
  Формат провода (аквариум):
  `{"v":1,"scr":0,"p":2,"pn":3,"nl":40,"sessions":[{"id":"abc12345","name":"proj","state":0,"sub":2,"mb":17}]}`
  Кофейня: `{"v":1,"scr":1,"cafe":{"st":2,"nm":750,"dow":0,"till":780,"om":540,"cm":1020,"net":380,"br":[[620,630,0],[720,780,1]]}}`
  Сон: `{"v":1,"slp":1}` — состав спящему экрану не нужен, гоняем короткую строку.
  `id` в снэпшоте **укорочен** (`Bridge.short_ids`, 8 символов, при коллизии длиннее):
  полный UUID не влезает в буфер `id[24]` прошивки — она обрезала бы молча и diff
  перестал бы различать сессии; плюс это 36 байт на карточку впустую.
- **Контракт мост↔прошивка проверяется автотестом.** `bridge/tests/test_contract.py` читает
  `octodash.ino`, вытаскивает поля, которые прошивка разбирает, и сверяет с тем, что мост
  реально отдаёт — в обе стороны. Там же сверяются коды состояний, число экранов, размеры
  буферов (`id[24]`, `name[20]`, `LINE_MAX`) и то, что худший снэпшот влезает в них.
  Рассинхрон протокола не поймает ни pytest моста, ни компилятор Arduino — только этот тест.
- **Коды состояний фиксированы enum'ом прошивки:** `WORKING=0, WAITING=1, IDLE=2, ERROR=3`.
- **Имя карточки готовит мост, не прошивка.** `display_name(cwd)` = `basename` →
  транслит RU→латиница (шрифт ESP — CP437, кириллицу не умеет) → обрезка по центру
  (`~`) до `OCTO_NAME_MAX`. Серединная обрезка намеренная: worktree с общим префиксом
  иначе схлопнулись бы в одинаковые огрызки. Прошивка остаётся «тупой» — рисует ASCII.
- **`MAX_SESSIONS=6`** (сетка 3×2) — это размер СТРАНИЦЫ, а не предел. Сессий обычно больше,
  поэтому мост **отбирает** (`paginate`): приоритет `WORKING`→`ERROR`→`WAITING`→`IDLE`, внутри
  группы — по свежести, дальше режется на страницы по 6; брошенные скрываются
  (`OCTO_STALE_IDLE_HOURS` для IDLE, `OCTO_STALE_ANY_HOURS` для любого состояния — статус тоже
  протухает) и на страницы не попадают вообще.
- **Страницу и экран держит мост, не прошивка.** ESP шлёт только событие ручки
  (`{"enc":"cw"|"ccw"|"key"|"hold"}`, с зажатой кнопкой `+"k":1`) и получает готовый снэпшот
  нужной страницы. Обратный канал читается **всегда**, а не только при `OCTO_DIAG` — по нему
  приходит энкодер. Первый щелчок из сна только будит и ничего не листает.
  **Отбор и раскладка — разные вещи:** *что* показать решает приоритет, а *где* показать — время
  старта сессии (`started_ms` из реестра, иначе `first_seen`), чтобы карточки не прыгали при смене
  статуса. Кого не видно и почему — `octoctl debug` / `GET /debug`.
- **Сверка с реестром Claude Code** (`~/.claude/sessions/<pid>.json`, `daemon/roster.json`,
  `jobs/*/state.json`, раз в `OCTO_REGISTRY_SEC`). Закрывает то, что PID-liveness не видит
  принципиально: сессию без PID (по PID бессмертна) и смену `session_id` внутри живого процесса
  (`/clear`, resume, fork → карточка-призрак). Плюс поднимает состав сразу после рестарта моста.
  Формат чужой и недокументированный, поэтому: непонятная запись пропускается; не прочитался реестр
  (`None`) или пуст — **ничего не удаляем**; молодые сессии защищены `OCTO_RECONCILE_GRACE_SEC`;
  живость записи = PID жив **и** `procStart` совпал (защита от переиспользования PID);
  `jobs/*/state.json` — только источник статуса (там лежат и завершённые задания).
- **Хуки не должны блокировать Claude.** Обработчик `POST /event` всегда быстро возвращает `200`;
  ошибки — в лог, никаких задержек. Обёртка `octo-notify.py` использует короткий таймаут запроса
  (~0.5с), глотает все ошибки и **всегда выходит с кодом 0**.

## Внутренности моста (целевой дизайн)

- **Конкурентность**: основной поток = HTTP-сервер (приём хуков); поток-reaper (проверка PID раз в
  `OCTO_REAPER_SEC`, дефолт 2с, пушит при изменении); таймер heartbeat (пуш раз в `OCTO_HEARTBEAT_SEC`,
  дефолт 5с — чтобы перезагруженный/переподключённый ESP восстановил картинку). Доступ к словарю
  `sessions` — под одним `threading.Lock`; запись в serial сериализовать под локом (или через
  очередь), чтобы строки не перемешивались.
- **Модель сессии** по ключу `session_id`: `{session_id, name, state, pid, first_seen, last_event,
  subagents, last_active_ms, started_ms, source, reg_name}`.
  `name = os.path.basename(cwd.rstrip('/'))` (даёт имена git-worktree / папок).
  `first_seen`/`last_event` монотонные (дебаунс, возраст), `last_active_ms`/`started_ms` — абсолютные
  (мс): переживают рестарт моста и сравнимы со временем из реестра, по ним считается «брошенность».
- **Конечный автомат** (событие → действие): `start`→создать сессию, `state=IDLE`, запомнить `pid`;
  `working`→WORKING; `waiting`→WAITING; `idle`→IDLE; `error`→ERROR; `end`→удалить сессию.
  Неизвестное событие → лог и игнор. Не-`start` событие для неизвестного `session_id` → создать
  сессию на лету с этим состоянием и `pid=None` (хук мог прилететь после рестарта моста).
- **Триггеры пуша**: любое видимое изменение состояния (с дебаунсом `OCTO_DEBOUNCE_MS`, дефолт 100мс,
  чтобы серия событий схлопнулась в один пуш) ИЛИ периодический heartbeat.
- **Устойчивость serial**: если порт недоступен (ESP не воткнут) — мост не падает: логирует,
  продолжает принимать хуки, периодически пытается переоткрыть порт; heartbeat перерисует после
  переподключения.

## Обвязка хуков

`octo-notify.py` читает JSON-конверт хука со stdin (`session_id`, `transcript_path`, `cwd`,
`hook_event_name`), мапит событие и шлёт `POST` на мост. Для `SessionStart` добавляет
`pid = os.getppid()` (родитель обёртки = процесс `claude` — единственный захват PID за сессию,
нужен для liveness).

Маппинг хук Claude Code → `event` моста:
`SessionStart`→`start` (+pid), `UserPromptSubmit`→`working`, `PostToolUse`→`working`,
`Notification`→`waiting`, `Stop`→`idle`, `SessionEnd`→`end`, `StopFailure`→`error` (опц.),
`PreToolUse` (matcher `Task|Agent`)→`subagent`, `SubagentStop`→`subagent_done`.
`PostToolUse`→`working` снимает «застревание» на `WAITING` после одобрения тула.
Регистрировать на **user-уровне** (`~/.claude/settings.json`), чтобы работало во всех
проектах и worktree.

**Суб-агенты.** `PreToolUse` вешается с **matcher `Task|Agent`** (фильтр по имени инструмента →
хук срабатывает только на спавн суб-агента, без спама; `Task` — историческое имя тула,
`Agent` — текущее). Мост держит `Session.subagents`: `subagent` +1 (мгновенный пузырёк при
спавне), дальше — **абсолютная синхронизация**: конверты `Stop`/`SubagentStop` несут
`background_tasks`, обёртка шлёт `"subs":N` (число задач type=subagent со status=running),
мост выставляет счётчик по нему. Тип фильтруется намеренно: счёт всех running-задач дал бы
вечный ложный пузырёк от собственного фонового shell'а сессии (dev-сервер и т.п.); цена —
субагент, приостановленный с живым фоновым ребёнком, теряет пузырёк до резюма (экзотика). Чистый ±1 ненадёжен: субагенты фоновые, `SubagentStop`
срабатывает на **каждую** остановку субагента (в т.ч. промежуточную, с живыми фоновыми
детьми), а конец хода родителя (`Stop`→`idle`) не значит, что субагенты закончились —
поэтому на `idle` счётчик НЕ сбрасывается (сброс только на `start`; `subagent_done` без
`subs` — фолбэк-декремент для старых конвертов). В снэпшот идёт
`"sub":N` (кап 5), прошивка рисует N пузырьков-искр на орбите вокруг осьминога.

PID для liveness определяет `resolve_claude_pid()` в обёртке: обход дерева процессов вверх и
матч по **имени** процесса/basename (`claude`/`claude.exe`/`claude-code`), не по подстроке во
всей cmdline (иначе ложно ловятся предки с `~/.claude/...` в аргументах). Не нашли уверенно →
`pid=None` (мост не реапит по liveness — безопаснее, чем убить карточку по PID транзиентного шелла;
такую сессию подберёт сверка с реестром — она же и подставит настоящий PID). Известная ловушка:
у `claude daemon run` имя процесса тоже `claude`, поэтому обход дерева из фоновой сессии
резолвит PID **демона-супервизора** — он живёт независимо от сессий, и карточка по нему
бессмертна. Настоящий PID воркера берётся из `daemon/roster.json` при сверке.


## Прошивка (firmware/octodash/octodash.ino)

Скетч построен на рабочей базе с проверенной анимацией; менять стиль отрисовки и
палитру без нужды не стоит. Специфика:
- Дисплей: `tft.setRotation(3)`; пины `TFT_CS=D8, TFT_DC=D3, TFT_RST=D4`.
- Плавность — через off-screen `GFXcanvas16 octoBuf(60,72)` на одного осьминога:
  кадр собирается в RAM, затем один `drawRGBBitmap` (без чёрной вспышки).
- `enum State { WORKING, WAITING, IDLE, ERR }` = 0,1,2,3 — совпадает с кодами моста.
- **Diff** в `applySnapshot()`: полная перерисовка (`redrawAll` = `drawGrid` + рамки)
  только если сменился состав / имя / статус — иначе `loop()` просто анимирует дальше.
  Heartbeat моста шлёт тот же снэпшот раз в 5с — diff видит «без изменений», лишней
  перерисовки нет.
- Пустые слоты (сессий < 6) — просто фон, без осьминога.
- Библиотеки: Adafruit GFX, Adafruit ILI9341, ArduinoJson (v6).

## Запуск и тестирование моста

```bash
# из bridge/
.venv/Scripts/python.exe bridge/bridge.py                # боевой режим
OCTO_MOCK=1 .venv/Scripts/python.exe bridge/bridge.py    # 6 фейковых сессий, без хуков
OCTO_DEBUG=1 .venv/Scripts/python.exe bridge/bridge.py   # видно строки «→ ESP: {...}»
```

Без железа посмотреть, что уходит на ESP: запустить с `OCTO_DEBUG=1` (каждый снэпшот
логируется) или дёрнуть `GET /status`.

**Разбор живого моста снаружи** (`octoctl.py`, он же HTTP): `octoctl status` — что на экране;
`octoctl debug` — всё состояние (сессии, PID, живость, тишина в часах, кто скрыт и почему,
счётчики пушей/сверок, состояние serial); `octoctl resync` — форс-сверка; `octoctl reset` —
забыть все сессии и пересобрать состав из реестра; `octoctl rm <префикс id>` — убрать карточку;
`octoctl restart` — перезапустить процесс; `octoctl shot` — **снимок экрана платы в PNG**. Эндпоинты: `GET /status`, `GET /debug`,
`GET /ui`, `POST /resync`, `POST /reset`, `POST /shot`, `DELETE /sessions/<id>`.

**Снимок экрана (`POST /shot` / `octoctl shot`).** Панель по SPI не читается (MISO не разведён),
поэтому «фотографирует» себя прошивка: на `{"cmd":"shot"}` она проходит экран плитками 68×76 той же
композицией, что рисует его вживую (`composeCurrentScreen`), и высыпает пиксели hex-строками в
serial между `{"esp":"shot"}` / `{"esp":"tile"}` / `{"esp":"shot_end"}`. Мост собирает PNG
(`ShotCollector` + `write_png`, только zlib — без внешних зависимостей). Смысл: визуальные баги
раньше ловились только глазами человека после заливки; теперь их видно из репозитория. Отдельной
версии отрисовки для снимка НЕТ намеренно — иначе снимок расходился бы с экраном.
Строки снимка сжаты (raw hex / `L`+серии / `#N` повтор строки — прошивка выбирает
короткую): сырой hex это 307 КБ, ~30с на снимок, и он не успевал дойти. Неполный снимок
не прячется (`complete` в ответе, предупреждение в `octoctl`) — обрыв выглядит как
«пропали карточки» и один раз уже сбил с толку.

**Отладка и прод — один код, флаги, а не две версии.** Отдельной отладочной версии нет
намеренно: два пути отрисовки в этом проекте уже расходились и стоили дня работы. В прошивке
два флага: `ESP_DIAG` (телеметрия boot/stat, по умолчанию 0) и `ESP_SHOT` (снимок экрана,
по умолчанию **1** — оставлен в проде, потому что это единственный способ увидеть панель
не стоя рядом с ней; цена 1.9 КБ статической памяти). Мост делить не на что: отладочные
эндпоинты (`/debug`, `/ui`, `/shot`, `/enc`) работают только по запросу — обработка хука
12 мкс, сборка `/debug` 0.5 мс, буфер снимка живёт только на время запроса. Верхний
предел флеша прошивки тоже не проблема: 281 КБ из ~1 МБ.

**Прошивку можно собирать и заливать из командной строки** — IDE не нужна:
`arduino-cli` лежит внутри установки Arduino IDE, ядра и библиотеки у него те же.
Порядок и грабли (мост держит порт → `PermissionError`) — в `firmware/BUILD.md`.

**Веб-морда** — `http://localhost:8787/` (то же на `/ui`): сводка, таблица всех сессий с
причинами скрытия, кнопки resync/reset/скрыть; опрашивает `/debug` раз в 2с. Страница
самодостаточна (HTML+CSS+JS инлайном в `UI_HTML`) — **никаких внешних CSS/JS/шрифтов**:
мост не должен зависеть от сети, чтобы показать своё состояние; в тестах это закреплено.
`GET /` различает клиента по `Accept`: браузер → морда, curl → снэпшот JSON (старый
контракт цел). `/favicon.ico` отдаёт 204, чтобы консоль браузера была чистой.

**`DELETE /sessions/<id>` скрывает, а не удаляет** (`Bridge.mute`): удалённую сессию сверка
вернула бы через `OCTO_REGISTRY_SEC`, и кнопка выглядела бы сломанной. Метка `muted_ms`
хранит уровень активности на момент скрытия; заглушка снимается сама, когда сессия подаст
признак жизни. Мусор, которого нет в реестре, всё равно добьёт сверка.

Чек-лист ручной проверки (Definition of Done):
- **Singleton**: запустить мост дважды — второй молча выходит с кодом 0, первый работает.
- **Liveness**: `POST /event` со `start` и живым PID, убить процесс — карточка исчезает
  в пределах `OCTO_REAPER_SEC`.
- **Дебаунс**: серия быстрых событий → на serial ровно один снэпшот (видно с `OCTO_DEBUG=1`).
- **Отключение ESP**: выдернуть USB на работающем мосту — мост не падает; воткнуть обратно —
  heartbeat перерисует.

Тест-фреймворка и шага сборки пока нет; при появлении тестов добавить `pytest`.
